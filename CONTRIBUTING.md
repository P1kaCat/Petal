# Contributing to Petal

All proposals and contributions go through the
[official GitHub repository](https://github.com/P1kaCat/Petal).

## Start with an issue

Use a bug report for reproducible failures or a feature proposal for ideas.
Describe the user problem, expected behavior, and relevant screenshots.
Discuss substantial changes before implementation. Email, Discord submissions,
and independent project releases are not part of the contribution process.

## Submit a pull request

1. Read [LICENSE](LICENSE) and the [development guide](docs/SETUP.md).
2. Create a GitHub contribution fork and a branch for your change.
3. Keep changes focused and link the related issue.
4. Run `pnpm test`. Installation changes may require the integration checks
   described in [VERIFICATION.md](VERIFICATION.md).
5. Include screenshots for UI changes and explain remaining limitations.
6. Open a pull request against `main` in the official repository.

Use English for documentation, issues, pull requests, and commit messages.
The application interface is English; keep new user-facing text in English
unless your proposal explicitly introduces localization.

## Contribution rights

Petal uses a restrictive source-available license. Local modifications and
contribution forks are permitted under its terms. Independent modified
releases, binaries, and mirrors are not. GitHub's own public-repository viewing
and forking permissions still apply.

You retain copyright in your contributions. Intentionally submitting a pull
request for inclusion grants the permissions in Section 5 of [LICENSE](LICENSE),
including the maintainer's right to include your work in official releases.
Only submit material you own or are authorized to contribute, and identify
third-party material and its license.

Never commit keys, tokens, credentials, personal instance data, Minecraft
downloads, or caches. Do not expose credentials or working security exploits in
public issues; use GitHub private vulnerability reporting if available.

The maintainer reviews proposals and decides whether to merge them.
