# Minecraft content in Petal

Project types are immutable: `mod`, `resourcepack`, `shader`, `datapack`, `modpack`. Existing projects remain mods. All types use the same author rights declaration, private upload/quarantine and moderator approval workflow. Public discovery filters by type; publication never changes an author's chosen content license.

Mods use `.jar` and a loader descriptor. Resource packs and datapacks use `.zip` with a valid `pack.mcmeta`. Shaders require source files under `shaders/` and a compatible shader runtime in Minecraft; Petal does not assume a shader loader is installed. Archives reject traversal, symbolic links, duplicate case-insensitive names, encryption, over 30,000 entries and over 1 GB declared expanded content. Uploaded files are not executed or extracted by the API.

In the launcher, open a profile and use **Packs for this world**. Select the content type, provider and project ID. Resource packs go to `resourcepacks`, shaders to `shaderpacks`, and datapacks to an explicitly selected existing world's `datapacks` folder. Required downloads are resolved and validated in a staging directory before installed files change. Checksum, permission, dependency or persistence failures roll back changed files and profile records. Existing unmanaged files cannot be overwritten; symlink directories are refused.

Petal modpacks are ZIP files containing `petal.index.json` in the versioned [manifest schema](../api/schemas/pack-v1.json). They reference at most 100 pinned provider files with source, project ID, version ID, checksum, content type and a safe target. Required mod dependencies are resolved through the provider APIs. Optional files are skipped unless the player checks **Include optional modpack files**. Downloaded content is capped at 1 GB per installation. The pack's Minecraft version and loader must match the selected profile. Bundled overrides and native Modrinth `.mrpack` / CurseForge manifest conversion are not supported in this format.

Petal resolves external files from their original APIs and approved CDN endpoints; it never mirrors external projects automatically. CurseForge files without an authorized API URL require manual download. CurseForge acceptance with a real approved key remains pending. Modrinth file hashes and CurseForge SHA-1 hashes are retained; no pack can invent an arbitrary external download URL.
